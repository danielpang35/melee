## Protect the working result
- Preserve accepted EX_v002 first-person source, native playback and projection; DEVELOPMENT identifies the baseline. Keep a reproducible benchmark with actual source/config/module identity. User-authorized runtime timing changes and separately identified isolated FP corrections are allowed while preserving that accepted source and benchmark. Technical promotion does not establish artistic or playable acceptance.
- Keep exploration separate from selected source, runtime and accepted assets. Batch generation/rendering must never auto-export, auto-import or promote. Retain editable source, controls, preview and a brief selection reason. Never automatically delete source or unique evidence.
- Check dirty state and coordinate before editing shared source or selection; preserve unrelated work. One owner controls shared selection and each writable Blender session.
- C++ owns legal inputs, attack clock, movement, blade contact and damage. FP/TP may differ visually but must communicate compatible phase, direction, reach and contact. Resolve significant disagreement explicitly; never silently change accepted gameplay to fit animation.
- Accels/drags use aim and footwork without changing playback rate. Keep manipulation inputs separate from neutral clips.

## Make animation iteration cheap
- Default to three distinct complete performances; expand to four–six only for useful additional hypotheses. An isolated defect or exact user edit can use one. Check shared grip/reference assumptions before multiplying candidates.
- Coauthor body, hands and weapon. Check every character from multiple angles: body/rig front, rear, left and right; animation complete source-speed primary and rear-quarter views. Use the same camera definitions across candidates. Never retime comparisons to hide mismatch.
- Select a provisional winner without asking for approval of each draft, then refine. After two passes without convincing gain, change choreography/controls or generate a new batch. Intentional stretch is allowed; preserve connected-looking grips and meaningful threat.
- Reuse Python/AnimationLab and native Blender/Unreal workflows. Save native curve edits before previews; do not regenerate from stale recipes. A new solver, rig, Control Rig or runtime compensation layer needs a demonstrated bottleneck and bounded experiment.
- Agents operate tools; Daniel directs and reviews. After two coherent batches reveal a persistent specialist limitation, prepare an actionable one-exchange animator brief and assets. Do not commission work or require Daniel to operate Blender.

## Verify the changed contract
- Follow [VALIDATION.md](VALIDATION.md). Animation drafts need usable inputs and cheap whole-action primary and rear-quarter previews, not engine imports, C++ builds, pose matrices or full regressions.
- Selected integration needs evidence for changed export/phase/contact behavior. Changed C++ needs a build and affected contract tests; consequential code/contact changes need one independent review. Preserve existing failures and assertions; reuse unchanged evidence.
- Documentation changes need relevant content/path checks only. Serialize heavy renders, imports and builds.
- Sampled frames, metrics and agent rankings do not prove continuous viewing or human acceptance. State evidence limits; leave missing evidence unscored. Keep developer diagnostics off player-facing surfaces. The 100–144 FPS mid-tier PC target is a target, not measured support.

## Coordinate without overhead
- Prefer one owner through refinement; delegate only bounded work that reduces total effort. Assign the objective, owned paths, protected baseline, smallest useful evidence and absolute rules path; animation assignments also include the absolute pipeline path. Recipients read these before acting. No child agents; notify active owners when governing instructions change.
- Use Astra High for unresolved architecture and detailed technical planning; lowest suitable effort for settled work. Avoid idle polling, repeated authority reads and duplicate reviews.
- Keep one compact checkpoint: selected candidate/source identity, visible change, relevant check, evidence limitation and next useful action. Record the policy ID once. Report usage only when measured, separating cached input, uncached input and output; raw totals are not allowance charges.
